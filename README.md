# Сайт репетитора

Веб-приложение для частного репетитора: расписание занятий, ученики и родители,
домашние задания и оценки, учёт оплат, уведомления на сайте и в Telegram, база
теоретических материалов. Три роли с разными правами: **репетитор**, **родитель**,
**ученик**.

Тип проекта: **веб-приложение** (SPA на React + REST API на FastAPI), разворачивается
одной командой `docker compose up`.

## Что умеет приложение

- **Расписание.** Серия занятий — правило «каждые N недель в такое-то время»; из серий
  автоматически порождаются занятия на 12 недель вперёд. Правка серийного занятия
  работает как в Google Calendar: «только это», «это и последующие», «все занятия».
- **Ученики и родители.** Карточки, привязка детей к родителю, учётки с паролями,
  которые создаёт репетитор.
- **Занятие.** Тема, формат (онлайн/офлайн), домашнее задание с файлами, оценки и
  статус выполнения домашки по каждому участнику.
- **Финансы.** Ставка за занятие, платежи родителей, вычисляемый баланс и долг,
  сводка по родителям и заработок по месяцам.
- **Уведомления.** Колокольчик на сайте и доставка в Telegram: напоминания о занятиях,
  публикация домашки, отмены и переносы, напоминания об оплате.
- **Теория.** Дерево тем произвольной глубины и материалы в Markdown с файлами,
  черновики и публикация, поиск по названиям.
- **Кабинеты.** Родитель видит детей, их занятия и свой баланс; ученик — только своё
  расписание, домашки и оценки.

## Стек и инструменты

| Слой | Технологии |
|---|---|
| Backend | Python 3.12, FastAPI, SQLAlchemy 2 (async, asyncpg), Alembic, pydantic v2, argon2 |
| База данных | PostgreSQL 16 |
| Frontend | React 18, TypeScript 5, Vite 5, Mantine 7, TanStack Query 5, FullCalendar 6, React Router 6 |
| Фоновые задачи | Отдельный контейнер `worker`: планировщик занятий, рассылка уведомлений, Telegram-бот (long polling) |
| Инфраструктура | Docker, docker compose, nginx (раздача статики и прокси `/api`) |
| Процесс | GitHub: Issues, Milestones, ветки по задачам, Pull request с code review |

## Быстрый запуск

```bash
cp .env.example .env      # заполнить пароли БД и учётку репетитора
docker compose up -d --build
```

Открыть `http://localhost/` и войти под логином репетитора из `.env`.
Подробности, локальная разработка и проверки — в
[инструкции по запуску](./docs/Инструкция%20по%20запуску.md).

## Как устроен репозиторий

- `backend/` — FastAPI-приложение (`routers → services → repositories`), модели,
  pydantic-схемы, чистая логика в `core/`, фоновые задачи в `worker/`.
- `frontend/` — React-приложение: `api/` (клиент и хуки), `pages/` по ролям, `components/`.
- `docs/` — техническая документация, планы и спецификации этапов.

## Процесс работы

Работа ведётся по спринтам. Каждая задача — Issue с меткой майлстоуна, под неё
заводится отдельная ветка и Pull request; ветка `main` меняется только через PR
после code review. Правила ветвления, ревью и состав задач по спринтам описаны в
[плане спринтов](./docs/План%20спринтов.md).
