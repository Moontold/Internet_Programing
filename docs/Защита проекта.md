## 2. Сценарий демонстрации

Стенд поднят заранее (`docker compose up -d --build`); в браузере открыты три окна:
репетитор, родитель, ученик (третье — в режиме инкогнито). Данные заведены заранее,
кроме того, что создаётся в ходе демо. Телефон с привязанным ВКонтакте родителя —
на трансляции экрана.

1. **Репетитор:** создать серию «Алгебра» для Маши по вторникам 17:00 → занятия появились
   на 12 недель вперёд.
2. Перенести одно занятие перетаскиванием → выбрать «Все занятия серии» → показать,
   что проведённые остались на месте.
3. Открыть прошедшее занятие: тема, домашка, прикрепить PDF, поставить оценку 5.
4. **Ученик:** обновить «Занятия» → домашка, файл и оценка; в колокольчике
   «Домашнее задание…».
5. **Родитель:** в колокольчике «Домашнее задание…» и «Задолженность…»;
   на телефоне — то же сообщение от бота ВКонтакте.
6. **Репетитор:** «Финансы» → внести платёж → у родителя плашки «Не оплачено»
   ушли у самых ранних занятий.
7. **Репетитор:** «Теория» → черновик материала с таблицей → ученик его не видит →
   опубликовать → ученик видит.
8. Показать телефонную вёрстку (DevTools, 360 px).

Резерв на случай сбоя ВКонтакте или сети: скриншоты шагов 5 и 7 в последнем слайде.

## 3. Ожидаемые вопросы

| Вопрос | Ответ | Отвечает |
|---|---|---|
| Почему баланс не хранится в БД? | Баланс зависит от платежей, ставок и статусов занятий; хранимое значение пришлось бы пересчитывать при каждой правке и легко рассинхронизировать. Вычисление — одна чистая функция в `core/`, проверяемая смоук-скриптом | Максим |
| Как не появляются дубли уведомлений? | Уникальный ключ дедупликации в таблице `notifications`; повторная вставка с тем же ключом игнорируется, поэтому перезапуск worker'а безопасен | Максим |
| Почему удалённое занятие не стирается из БД? | Строка держит место в серии, иначе worker породил бы занятие заново | Максим |
| Как защищён вход? | argon2, httpOnly-cookie, блокировка после 10 неудач за 15 минут, проверка `Origin` против CSRF | Максим |
| Что будет без ключа ВКонтакте? | Рабочий режим: бот не стартует, уведомления остаются на сайте | Максим |
| Почему нет юнит-тестов? | Так зафиксировано в ТЗ (раздел 8): чистая логика проверяется смоук-скриптами, API — сквозными прогонами, интерфейс — тест-кейсами приёмки | Павел |
| Как распределялась работа? | По ролям из плана спринтов: PM — требования, приёмка, отчёты; frontend — дизайн и интерфейс; backend — API, worker, деплой. Каждый PR ревьюил участник команды и преподаватель | Павел |
| Что изменилось по ходу проекта? | По отзывам заказчика после спринта 2 добавлены цвет занятий, перенос проведённого занятия и удаление учеников и родителей (Issues #30–#33) | Павел |
| Как адаптирован интерфейс к телефону? | Меню в нижней панели, вместо календаря — список недели, проверка на 360 px | Кирилл |
