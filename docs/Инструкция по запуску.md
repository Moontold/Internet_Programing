# Инструкция по запуску

[← К README проекта](../README.md)

Документ описывает, как поднять проект «Сайт репетитора»: полный стенд в Docker
и режим локальной разработки. Проверено на Windows 11 (Docker Desktop), macOS и Linux.

## 1. Что нужно установить

| Инструмент | Версия | Зачем |
|---|---|---|
| Docker + docker compose | Docker Desktop 4.x / Docker Engine 24+ | Запуск всего стенда одной командой |
| Git | 2.40+ | Клонирование репозитория |
| Python | 3.12 | Только для локальной разработки backend без Docker |
| Node.js | 20 LTS | Только для локальной разработки фронтенда без Docker |

## 2. Запуск в Docker (основной способ)

```bash
git clone https://github.com/Moontold/Internet_Programing.git
cd Internet_Programing

cp .env.example .env          # Windows PowerShell: copy .env.example .env
# открыть .env и задать POSTGRES_PASSWORD, TUTOR_LOGIN и TUTOR_PASSWORD

docker compose up -d --build
```

Поднимаются четыре контейнера: `postgres`, `backend`, `worker` и `frontend`. При старте
backend сам применяет миграции базы данных (`alembic upgrade head`) и, если репетитора ещё
нет, создаёт его учётку из `TUTOR_LOGIN`, `TUTOR_PASSWORD` и `TUTOR_NAME`. Учётки родителей
и учеников потом заводит репетитор, регистрации снаружи нет. `worker` стартует после того,
как backend ответил на проверку готовности, и в фоне порождает занятия из серий, переводит
прошедшие занятия в «проведено» и чистит истёкшие сессии.

Через минуту открыть `http://localhost/`. Стартовая страница показывает состояние
системы:

```
Backend        ok, версия 0.1.0
База данных    ok
Часовой пояс   Europe/Moscow
```

Полезные команды:

```bash
docker compose ps             # состояние контейнеров
docker compose logs -f backend  # логи backend
docker compose logs -f worker   # логи фоновых задач
docker compose down           # остановить стенд (БД и файлы сохраняются в томах pgdata и uploads)
docker compose down -v        # остановить и удалить данные БД и загруженные файлы
```

### Если порт 80 занят

На сервере, где уже есть другой сайт, задать в `.env` свободный порт и согласованный
с ним `APP_ORIGIN`:

```env
FRONTEND_PORT=8081
APP_ORIGIN=http://localhost:8081
```

## 3. Переменные окружения

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `POSTGRES_DB` | Имя базы данных | `tutor` |
| `POSTGRES_USER` | Пользователь БД | `tutor` |
| `POSTGRES_PASSWORD` | Пароль БД — **обязательно поменять** | `change-me` |
| `DB_HOST` | Хост БД; внутри compose переопределяется на `postgres` | `postgres` |
| `DB_PORT` | Порт БД | `5432` |
| `TUTOR_LOGIN` | Логин репетитора, создаётся при первом старте | `teacher` |
| `TUTOR_PASSWORD` | Пароль репетитора, не короче 8 символов — **обязательно поменять** | `change-me-too` |
| `TUTOR_NAME` | Имя репетитора в интерфейсе | `Репетитор` |
| `APP_ORIGIN` | Внешний адрес сайта: с ним сверяется `Origin` изменяющих запросов (защита от CSRF); при `https://` cookie сессии получает флаг `Secure` | `http://localhost` |
| `APP_TIMEZONE` | Часовой пояс отображения времени | `Europe/Moscow` |
| `SESSION_DAYS` | Срок жизни сессии в днях, продлевается при использовании | `30` |
| `SCHEDULE_HORIZON_WEEKS` | На сколько недель вперёд порождаются занятия из серий | `12` |
| `UPLOAD_DIR` | Каталог файлов домашних заданий; в Docker это том `uploads` | `/data/uploads` |
| `MAX_UPLOAD_MB` | Лимит размера одного файла, МБ; должен совпадать с `client_max_body_size` в `frontend/nginx.conf` | `50` |
| `FRONTEND_PORT` | Внешний порт nginx | `80` |

Файл `.env` в репозиторий не коммитится: в git хранится только шаблон `.env.example`.

`TUTOR_*` читаются только при первом старте, пока в базе нет репетитора. Чтобы потом
сменить пароль, репетитор меняет его сам (`POST /api/auth/change-password`); правка `.env`
на существующую учётку не влияет.

## 4. Локальная разработка без Docker

База данных всё равно поднимается в Docker, приложения запускаются с машины.

1. Создать `docker-compose.override.yml` (он в `.gitignore`) и пробросить порт БД наружу:

   ```yaml
   services:
     postgres:
       ports: ["15432:5432"]
   ```

   Затем `docker compose up -d postgres`.

2. Backend:

   ```bash
   python -m venv .venv
   source .venv/bin/activate        # Windows: .venv\Scripts\activate
   pip install -r backend/requirements.txt
   cp .env backend/.env             # в backend/.env поставить DB_HOST=localhost, DB_PORT=15432
                                    # и UPLOAD_DIR=./uploads (каталог в .gitignore)
   cd backend
   alembic upgrade head             # применить миграции (в Docker это делается при старте)
   uvicorn app.main:app --reload --port 8000
   ```

   Фоновые задачи запускаются отдельным процессом из того же каталога:
   `python -m app.worker.main`.

   Swagger UI: `http://localhost:8000/api/docs`. Изменяющие запросы проходят проверку
   `Origin`, поэтому для локальной разработки в `backend/.env` ставится
   `APP_ORIGIN=http://localhost:5173`, а Swagger открывается через прокси Vite:
   `http://localhost:5173/api/docs`.

3. Frontend:

   ```bash
   cd frontend
   npm install
   npm run dev
   ```

   Vite поднимется на `http://localhost:5173` и проксирует `/api` на `localhost:8000`.
   Если порт 5173 занят, Vite молча возьмёт следующий свободный — тогда в `.env`
   нужно указать именно его в `APP_ORIGIN`.

## 5. Проверка работоспособности

| Что проверяем | Команда | Ожидаемый результат |
|---|---|---|
| API отвечает | `curl http://localhost/api/ping` | `{"error":false,"message":"pong","payload":null}` |
| Backend видит БД | `curl http://localhost/api/health` | в `payload.database` значение `ok` |
| Репетитор входит | `curl -i -X POST http://localhost/api/auth/login -H 'Origin: http://localhost' -H 'Content-Type: application/json' -d '{"login":"teacher","password":"<TUTOR_PASSWORD>"}'` | `Set-Cookie: session=…; HttpOnly`, в `payload.role` значение `tutor` |
| Без входа доступа нет | `curl -i http://localhost/api/auth/me` | `401`, `{"error":true,"message":"Требуется вход",…}` |
| Миграции совпадают с моделями | `docker compose exec backend alembic check` | `No new upgrade operations detected.` |
| Модули backend импортируются | `cd backend && python scripts/smoke_import.py` | список модулей со статусом `ok` |
| Логика расписания считает верно | `cd backend && python scripts/smoke_schedule.py` (без БД и `.env`) | все строки `ok`, в конце `ALL OK` |
| Worker работает | `docker compose logs worker` | `Scheduler started, tz=Europe/Moscow, horizon=12 weeks` |
| Фронтенд собирается и проходит проверку типов | `cd frontend && npm run build` | сборка без ошибок, каталог `dist` |

## 6. Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `port is already allocated` | Порт 80 занят — задать `FRONTEND_PORT` в `.env` и перезапустить |
| На странице «Backend недоступен» | Backend не поднялся: `docker compose logs backend` |
| `worker` в статусе `Created` и не стартует | Ждёт готовности backend — смотреть `docker compose logs backend` |
| В `payload.database` ошибка подключения | Не совпали параметры БД в `.env`; при смене пароля после первого запуска нужен `docker compose down -v` |
| `pydantic_settings` ругается на отсутствующее поле | Не создан `.env` или в нём нет обязательной переменной (в том числе `TUTOR_LOGIN`, `TUTOR_PASSWORD`) |
| `403 Запрос отклонён: чужой источник` | Адрес, с которого открыт сайт, не совпадает с `APP_ORIGIN` — поправить `.env` и перезапустить backend |
| «Файл больше N МБ» или `413 Request Entity Too Large` | Файл превышает `MAX_UPLOAD_MB` или лимит nginx — поднять оба значения одинаково |
| «Слишком много неудачных попыток входа» | 10 неверных паролей за 15 минут по этому логину — подождать 15 минут |
| Backend не стартует: «Логин … уже занят» | `TUTOR_LOGIN` совпал с логином родителя или ученика — задать другой |
