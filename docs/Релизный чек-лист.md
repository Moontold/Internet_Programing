# Релизный чек-лист

[← К README проекта](../README.md) · [Инструкция по запуску](./Инструкция%20по%20запуску.md)

Чек-лист проходит project manager перед сдачей проекта на **чистой машине**: без
предустановленного проекта, без помощи разработчиков, только по документации из
репозитория. Каждый пункт отмечается «да» или номером Issue с найденным дефектом.
Итог прогона публикуется комментарием в Issue #17.

## 1. Репозиторий

- [ ] Все Issues спринтов 1–4 закрыты или перенесены с указанием причины в самом Issue.
- [ ] Все Pull request'ы влиты после Approve преподавателя; открытых PR нет.
- [ ] В `main` нет `.env`, токенов и паролей: `git log -p | grep -iE "token|password="`
      находит только шаблон `.env.example` и документацию.
- [ ] `.env.example` содержит все переменные, которые читает backend, с комментариями.

## 2. Развёртывание с нуля

- [ ] `git clone` → `cp .env.example .env` → задать `POSTGRES_PASSWORD`, `TUTOR_LOGIN`,
      `TUTOR_PASSWORD`, `TUTOR_NAME`, `APP_ORIGIN`.
- [ ] `docker compose up -d --build` завершается без ошибок.
- [ ] `docker compose ps`: `postgres`, `backend`, `worker`, `frontend` в состоянии `running`
      (`healthy`, где есть healthcheck).
- [ ] Миграции применились сами: в логе backend нет ошибок Alembic.
- [ ] Наружу открыт только порт фронтенда: `docker compose ps` не показывает
      опубликованных портов у `postgres`, `backend` и `worker`.
- [ ] `http://localhost/api/health` отвечает `ok` для backend и БД.
- [ ] Репетитор входит учёткой из `.env`.

## 3. Сценарии по ролям

Прогоняются тест-кейсы из документов требований; в итог прогона вносится только результат по блоку.

- [ ] Ядро: ТК-01 – ТК-32 ([спринт 2](./Требования/Спринт%202.%20Ядро%20системы.md)).
- [ ] Финансы и уведомления: ТФ-01 – ТФ-13, ТУ-01 – ТУ-15, ТЦ-01 – ТЦ-03
      ([спринт 3](./Требования/Спринт%203.%20Финансы%20и%20уведомления.md)).
- [ ] ВКонтакте и теория: ТВ-01 – ТВ-11, ТТ-01 – ТТ-11
      ([спринт 4](./Требования/Спринт%204.%20ВКонтакте%20и%20теория.md)).

## 4. Удаление учеников и родителей (Issues #32, #33)

- [ ] Удаление ученика из группового занятия: занятие и серия остаются у второго ученика.
- [ ] Удаление родителя: исчезают он, его дети, их занятия, платежи, уведомления
      и привязки ВКонтакте; файлы домашек удалены из тома `uploads`.
- [ ] Окно подтверждения перечисляет, что будет удалено.

## 5. Пустой ключ ВКонтакте

- [ ] С пустым `VK_GROUP_TOKEN` стенд поднимается, сайт и колокольчик работают,
      worker не падает, в профиле «Уведомления во ВКонтакте не настроены».

## 6. Сохранность данных

- [ ] `docker compose down` → `docker compose up -d`: пользователи, занятия, платежи,
      файлы и материалы на месте; пользователь остаётся в системе.
- [ ] `docker compose up -d --build` поверх работающего стенда не теряет данные.
- [ ] Повторный старт не создаёт второго репетитора и не меняет его пароль.

## 7. Интерфейс

- [ ] Все страницы трёх ролей работают на ширине 360 px (DevTools, iPhone SE):
      нет горизонтальной прокрутки, кнопки доступны.
- [ ] Проверены браузеры: Chrome, Firefox, Safari (или WebKit), Edge.
- [ ] Загрузка, пустые списки и ошибки выглядят единообразно; тексты на русском.
- [ ] `npm run build` во `frontend` завершается без предупреждений TypeScript.

## 8. Безопасность

- [ ] Cookie `session` с флагами `HttpOnly` и `SameSite=Lax`; при `APP_ORIGIN` на
      `https://` — ещё `Secure`.
- [ ] Изменяющий запрос с чужим `Origin` получает `403` (ТК-31).
- [ ] Файл больше 50 МБ отклоняется и backend'ом, и nginx (`413`).
- [ ] Файлы чужих занятий и черновиков недоступны (ТК-24, ТТ-06).

## 9. Документация

- [ ] README: описание, стек, команда, ссылки на ТЗ, план спринтов, инструкцию, API,
      руководство пользователя — все ссылки открываются на GitHub.
- [ ] ТЗ совпадает с реализацией: каждое ФТ и НФТ проверено в разделах 2–8; расхождения
      исправлены в ТЗ или заведены Issue.
- [ ] Каждый документ из `docs/` открывается из README напрямую или по цепочке ссылок.
- [ ] `docs/Инструкция по запуску.md` воспроизводится без подсказок (пункты раздела 2).
- [ ] `docs/API.md` перечисляет все эндпоинты из Swagger UI.
- [ ] `docs/Руководство пользователя.md` совпадает с интерфейсом: названия пунктов меню,
      кнопок и сообщений.
