## 1. Привязка ВКонтакте

### 1.1 Настройки

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `VK_GROUP_TOKEN` | Ключ доступа сообщества с правом «Сообщения сообщества» | пусто — бот выключен |
| `VK_GROUP_ID` | Числовой ID сообщества: нужен для Bots Long Poll и ссылки `https://vk.me/club<ID>` | пусто |
| `VK_LINK_CODE_TTL_MINUTES` | Время жизни кода привязки | `15` |

Имена переменных окончательно фиксирует Issue #20; если они изменятся, этот раздел
обновляется в том же PR.

### 1.2 Состояния привязки в профиле

| Состояние | Что показывает карточка «ВКонтакте» в профиле | Доступные действия |
|---|---|---|
| Бот не настроен (`VK_GROUP_TOKEN` пуст) | «Уведомления во ВКонтакте не настроены. Все уведомления приходят на сайт.» | нет |
| Не привязано | «Привяжите ВКонтакте, чтобы получать уведомления в сообщениях.» | «Получить код» |
| Код выдан и действует | Код крупными цифрами, «Действует до 17:45», ссылка «Написать сообществу», инструкция «Отправьте этот код в сообщения сообщества» | «Получить новый код» |
| Код истёк | «Код устарел. Получите новый.» | «Получить код» |
| Привязано | «ВКонтакте привязан. Уведомления приходят в сообщения сообщества.» | «Отвязать» |
| Привязка снята из-за запрета сообщений | «Привязка снята: вы запретили сообщения от сообщества. Разрешите их и привяжите заново.» | «Получить код» |

### 1.3 Основной сценарий

1. Пользователь в «Профиле» нажимает «Получить код».
2. Система выдаёт шестизначный код (`000000`–`999999`, случайный, уникальный среди
   действующих кодов) и время окончания действия — через 15 минут.
3. Пользователь открывает ссылку «Написать сообществу» и отправляет код сообщением.
4. Бот находит код, сохраняет идентификатор диалога (`peer_id`) за пользователем, удаляет
   код и отвечает: «Готово! Уведомления с сайта репетитора для <ФИО> будут приходить сюда.»
5. Карточка в профиле при следующем обновлении показывает «ВКонтакте привязан».
6. Следующее созданное уведомление приходит и в колокольчик, и во ВКонтакте.

### 1.4 Ветвления и тексты

| № | Ситуация | Поведение | Текст |
|---|---|---|---|
| В-1 | Бот не настроен, пользователь нажимает «Получить код» (через API) | Код не выдаётся | «Бот ВКонтакте не настроен. Уведомления приходят только на сайт.» |
| В-2 | Повторное «Получить код», пока старый действует | Старый код аннулируется, выдаётся новый на 15 минут | — |
| В-3 | Сообщение «Начать» (кнопка при первом входе в диалог) или «начать» в любом регистре | Бот отвечает приветствием | «Здравствуйте! Это бот сайта репетитора. Чтобы получать уведомления, откройте профиль на сайте, нажмите «Получить код» и пришлите код сюда.» |
| В-4 | Сообщение из 6 цифр, код не найден | Привязки нет | «Код не найден. Проверьте цифры или получите новый код в профиле на сайте.» |
| В-5 | Сообщение из 6 цифр, код истёк | Привязки нет, код удаляется | «Код устарел. Получите новый код в профиле на сайте.» |
| В-6 | Пять неверных кодов от одного диалога за 15 минут | Следующие коды от этого диалога 15 минут не проверяются | «Слишком много неверных кодов. Попробуйте через 15 минут.» (один раз) |
| В-7 | Любое другое сообщение (текст, стикер, вложение) | Бот не отвечает | — |
| В-8 | Пользователь уже привязан и присылает новый код с другого аккаунта ВКонтакте | Привязка переходит на новый диалог | Текст основного сценария |
| В-9 | Один аккаунт ВКонтакте привязывают два пользователя сайта (например, родитель и ребёнок с одного телефона) | Разрешено: оба получают уведомления в один диалог | Текст основного сценария |
| В-10 | Пользователь нажимает «Отвязать» | Привязка удаляется, неотправленные уведомления во ВКонтакте не досылаются | «ВКонтакте отвязан. Уведомления приходят только на сайт.» (на сайте) |
| В-11 | Пользователь запретил сообщения от сообщества (ошибка VK API 901) | Привязка снимается автоматически, уведомление остаётся на сайте | Состояние «Привязка снята…» в профиле |
| В-12 | Деактивированный пользователь | Код не выдаётся (войти он не может), уведомления ему не создаются | — |
| В-13 | Пользователь удалён (Issue #33) | Привязка удаляется вместе с ним | — |
| В-14 | Ключ задан, но неверный или отозван | Бот и доставщик пишут ошибку в лог и повторяют подключение раз в минуту; сайт работает | — |

## 2. Доставка уведомлений во ВКонтакте

1. Доставщик в `worker` берёт уведомления привязанных пользователей, созданные
   **после** привязки и ещё не доставленные. Старые уведомления после привязки
   не досылаются.
2. Текст сообщения — текст уведомления и ссылка на связанную страницу сайта
   (`APP_ORIGIN` + путь из матрицы переходов спринта 3).
3. Ошибка отправки → повтор с паузой 1, 5, 15, 60 минут; после 5 неудачных попыток
   уведомление помечается «не доставлено» и больше не отправляется.
4. Ошибка 901 (сообщения запрещены) не повторяется: привязка снимается сразу (В-11).
5. Отметка «прочитано» на сайте и доставка во ВКонтакте независимы.
6. При пустом `VK_GROUP_TOKEN` бот и доставщик не стартуют; в логе worker'а одна
   строка «VK bot disabled: VK_GROUP_TOKEN is empty».

## 3. Раздел «Теория»

### 3.1 Структура

- **Тема** — узел дерева: название (1–200 символов) и порядковый номер среди соседей.
  Тема может содержать подтемы и материалы.
- **Глубина** — до шести уровней: корневая тема — уровень 1. Создание подтемы на
  уровне 7 отклоняется: «Нельзя создать тему глубже шести уровней».
- **Материал** — лежит в теме: название (1–200 символов), текст в Markdown, файлы,
  состояние и порядковый номер среди материалов темы.
- Перемещение темы или материала в другую ветку в этой версии не поддерживается.
  Можно только менять порядок среди соседей.

### 3.2 Состояния материала

| Состояние | Кто видит | Как меняется |
|---|---|---|
| Черновик (по умолчанию у нового материала) | Только репетитор; в дереве помечен «Черновик» | Переключатель «черновик / опубликован» в редакторе |
| Опубликован | Все роли | Тем же переключателем; снятие публикации сразу скрывает материал |

### 3.3 Видимость по ролям

| Что | Репетитор | Родитель и ученик |
|---|---|---|
| Темы | Все, включая пустые | Только те, в ветке которых есть хотя бы один опубликованный материал |
| Материалы | Все | Только опубликованные |
| Черновик по прямой ссылке | Открывается | «Материал не найден» (не «Нет доступа»), `200` с `error: true` |
| Файл черновика | Скачивается | `404`, «Файл не найден» |
| Тема без опубликованного по прямой ссылке | Открывается | «Тема не найдена» |
| Создание, правка, удаление, порядок | Да | Нет: `403` |
| Число материалов в ветке | Все материалы | Только опубликованные |

### 3.4 Порядок и удаление

- Кнопки «Выше» и «Ниже» меняют местами соседние темы или материалы. У первого
  элемента «Выше» неактивна, у последнего — «Ниже».
- Новый элемент добавляется последним среди соседей.
- Удаление темы спрашивает подтверждение с составом: «Удалить тему «<название>»?
  Вместе с ней удалятся подтем: N, материалов: M, файлов: K. Действие нельзя отменить.»
  После подтверждения удаляется всё поддерево вместе с файлами в хранилище.
- Удаление материала спрашивает подтверждение и удаляет его файлы.

### 3.5 Поиск

- Строка поиска над деревом; поиск идёт по названиям тем и материалов, без учёта регистра
  (в том числе для кириллицы), по подстроке.
- Запрос короче двух символов (без учёта пробелов по краям) не отправляется; через API —
  «Введите не меньше двух символов».
- Не больше 50 результатов: сначала темы, затем материалы, внутри — по алфавиту.
  У каждого результата показывается навигационная цепочка.
- Родитель и ученик находят только то, что видят в дереве.

### 3.6 Отображение материала

- Markdown по GFM: заголовки, списки, таблицы, ссылки, код, зачёркивание, списки задач.
- Сырой HTML не исполняется и показывается как текст.
- Внешние ссылки открываются в новой вкладке (`rel="noopener noreferrer"`).
- Картинку из прикреплённого файла можно вставить ссылкой на файл:
  `![подпись](/api/files/<id>)`.
- Над материалом — навигационная цепочка «Теория / Тема / Подтема».
- В редакторе есть предпросмотр и шпаргалка по разметке.
- Файлы материала — до 50 МБ каждый, как у домашек.
